# 交接文档

最后更新：2026-11-06 · 对应版本 **1.2.1** · 给接手的开发者或 AI 代理

这份文档只讲「工程现在是什么样、这轮改了什么、哪里有坑」。使用说明看 `README.md`，工作台的业务规则看 `docs/改模工作台-逻辑拆分.md`，导入边界条件的逐条清单看 `docs/工作台导入-边界条件清单.md`。

## 1. 这是什么

管理 VRChat 改模素材的 Windows 桌面程序。前端是一套纯静态页面（`renderer/`），跑在 Tauri 的 WebView2 里；后端是进程内的 Rust（`src-tauri/`）。没有本地 HTTP 服务、没有端口、没有令牌，前端通过 `invoke` 调 Rust 的路由表。

产物是仓库根目录的 `VRCLib.exe`，必须和 `WebView2Loader.dll` 同目录。

## 2. 技术栈与关键版本

| 项 | 值 |
|---|---|
| 界面 | 原生 JS，无框架，23 个模块按编号顺序 `<script>` 引入 |
| 宿主 | Tauri 2 + Rust，`src/host/mod.rs` 是路由表 |
| 存储 | SQLite（`library.db`，rusqlite bundled）+ 若干 JSON 状态文件 |
| 工具链 | `stable-x86_64-pc-windows-gnu` + MinGW-w64（本机没有 MSVC C++ 工作负载） |
| 前端产物 | 编译期嵌进 exe（`tauri.conf.json` 的 `frontendDist = ../renderer`），依赖 `custom-protocol` 特性 |

## 4. 不能破的约定

1. **工作台只往这几个位置写**：`Assets/VRCAL_Imports/`（导入产物）、`Assets/Editor/`（安装助手）、`Library/VrclibBridge/`（文件桥）、以及数据目录。别的地方一律不碰。
2. **浏览/扫描/解析全程只读**，写入只发生在用户点按钮之后。
3. **删除走回收站**，工作台自己产生的目录才自动清理，且必须有登记（见 §6.3）。
4. **前端改了要重建 exe 才生效**：`frontendDist` 是编译期嵌入，`cargo` 不会因为 JS/CSS 改了而重编。改完 `touch src/main.rs` 再构建，或用 `热更新.bat`。
5. **版本号有 5 处**，改的时候一起改：`Cargo.toml`、`tauri.conf.json`、`main.rs` 的 `TITLE` 与关于对话框、`index.html`、`00-data.js` 的 `APP.version`。顶栏那行文字是 `90-main.js` 用 `APP.version` 覆盖写的，**只改 index.html 不生效**。

## 5. 2026-11 这一轮改了什么

### 5.1 导入边界条件修复（P0/P1 共 20 余项）

集中在 `workbench_api.rs`。要点：

| 主题 | 实现 |
|---|---|
| 解压目录只能删自己产的 | 新增登记表 `extract-roots.json`（`register_extract_root` / `is_extract_root` / `remove_extract_dir`），只有 `extract_zip_beside` 产出的目录才登记；`cleanupDir` 传陌生路径直接不删，返回 `cleanedUp:false` |
| 解压前判重叠 | `import_path_sync` 在解压**之前**做 `overlap` 检查，压缩包放在工程里直接拒绝 |
| 同名不覆盖 | `copy_any` 改成「已存在就跳过」，返回 `copied / skipped / bytes` |
| 勾选导入查 GUID | `import_selected_sync` 逐个 pick 调 `find_conflicts`，命中报错并指出冲突文件 |
| 加密包不再静默出 0 字节 | `io::copy` 的错误不再 `let _ =`，失败即中止并清理半成品 |
| 非法文件名 | `unsafe_name_component` 提前判 `? : * " < > \|`、结尾点/空格、`CON/NUL/COM1` 等 |
| 单个包失败不拖垮整批 | 失败记成 `{ok:false, state:"failed", message}` 的 job，文件夹部分照常完成 |
| 空目录不算成功 | `execute_sync` 遇到 0 文件直接报错 |
| 被忽略的内容要说 | 统一写 `notes`，前端在任务条显示「注意：…」 |
| 进程内互斥 | `ROOTS_LOCK` / `CLEANUP_LOCK` 两把 `Mutex`，防止并发导入把 JSON 登记覆盖掉 |

### 5.2 B5：替换旧版本

- 预检侧 `replaceable_dir(conflicts, material)` 判断两件事：冲突是否**全部**落在同一个导入目录（散在多个目录就不是同一素材）、那个目录名是否以本素材名开头
- 执行侧 `trash_import_dir` 再独立验一遍，不信任前端传来的路径：必须以 `Assets/VRCAL_Imports/` 开头、只允许一层（不能是整个 `Imports`）、目录里必须有 `.vrcal-import.json` 回执
- 动作：旧目录 `rename` 到 `<数据目录>/trash/<名>-<时间戳>`；新内容一个文件都没写成功时用 `restore_import_dir` 放回去
- `plan` 返回 `replaceable` / `replaceDir`，`ready = 无冲突 || 可替换 || 可续传`
- 无 GUID 冲突时，额外要求回执签名与本次内容一致才给替换（防同名不同素材被换掉）

### 5.3 导入队列悬浮窗

`renderer/js/91-workbench.js` 模块级 `taskPanel`：

- `openTaskPanel()` 建面板（`#wbImportPanel`），`taskPanelSetCollapsed()` 收起成 40px 竖条，`taskPanelDestroy()` 销毁
- 收起态是一条独立的 `<button class="wb-task-strip">`，**不能复用标题栏**——标题栏上有拖拽（`mousedown` 里 `preventDefault`），点击会被吃掉
- 面板 API：`start(total)` / `progress(done,total)` / `finish(ok,bad)` / `action(text, fn)`（临时动作按钮，用来放「更新 Unity 助手」）
- 工作台标题栏还有常驻入口 `queueEntry`，`refreshQueueEntry()` 各处同步
- z-index 520：要盖住工作台整页（400）与下载面板（480），但不能盖弹窗（900）

### 5.4 解压目录层级勾选

- 后端 `list_extract` 改为递归 `walk_list`，返回扁平列表 `{path,name,dir,depth,files,size,package}`；目录在前、同级按名字排序；跳过隐藏项、`__MACOSX`、`*.meta`；上限 2000 节点 / 8 层，超出返回 `truncated`
- 勾选语义：只把「最上层被勾选」的节点发给后端
- `import_selected_sync` 的目标路径保留相对结构，顶层 `Assets` 仍然剥掉。以前 `A/Textures` 和 `B/Textures` 会撞成同一个目录

### 5.5 关闭确认与断点续传

- 前端 `setHostBusy(true)` 在队列开始时租一个「忙」的租约，40 秒续一次、2 分钟有效；`main.rs` 的 `WindowEvent::CloseRequested` 里调 `import_busy_now()`，忙则 `prevent_close()` 并 `emit("wb-busy-close")`，页面弹确认后再调 `/api/wb/quitNow`
- 复制改成 `copy_file_atomic`：先写 `xxx.vrcalpart` 再 rename
- 目标目录写 `.vrcal-importing` 标记，完成才删；再次导入同一素材看到标记就按续传处理（`resuming`），只补缺的文件
- 队列每推进一项把剩余项存进 `workbench.json` 的 `resume`，下次启动 `offerResume()` 弹「继续上次导入」，旁边有「忽略」

### 5.6 队列卡死修复（本轮最重要的 bug）

**现象**：unitypackage 导完了、记录显示成功，队列一直停在「已把包发给 Unity」。

**根因**：`waitTerminal(ids, done)` 里调用的是 `done(字符串)`，两个调用点却写成 `function (rs) { rs.every(...) }`——`rs.every is not a function` 抛异常，`advance()` 再也不执行。记录是另一条链路（`checkReceipt` 每 3 秒轮询）更新的，所以一个对一个错。

**现在的契约**：`done(status, message)`，`status ∈ ok | fail | pending`。

- 三路结论取其一：本地 `state.jobs` 里同 `requestId` 的终态、Unity 回执、15 分钟看门狗
- `settled` 幂等，迟到回调不会推进两次
- `cancelled` / `blocked` 从「算成功」改成失败；Unity 没开导致的排队记 `pending`，不算成功

### 5.7 Unity 助手心跳

- `assets/unity/VrclibImportBridge.cs` 新增 `BridgeVersion = 2`，每 5 秒写 `Library/VrclibBridge/bridge.json`：`{version, at, active, phase, editor}`
- Rust 侧 `bridge_heartbeat(root)` 读文件 mtime，判定 `alive`（30 秒内）/ `stale` / `missing`；`receipt_sync` 把 `bridge`、`bridgeVersion`、`bridgeCurrent`、`active` 一起返回
- 前端据此换文案，并在 `missing` / 版本不符时给「更新 Unity 助手」按钮（`installBridge` + `update:true`）
- **两边版本号要一起改**：C# 的 `BridgeVersion` ↔ Rust 的 `BRIDGE_PROTOCOL_VERSION`

### 5.8 素材库导入判重与目录命名（2026-11-06）

两处补漏，都是为了「外人导出的包」和「同一素材的第二版」这两种情况。

**判重补上链接档**。素材包导入用的 `findExisting2`（`89-pack.js`）原来只有 同源 ID → 商品 ID → 标题全等 三档，对方改过标题又没有商品 ID 就认不出来；而按链接查重的 `App.findDuplicate` 只在用户脚本 / 订单同步那条路上用。现在 `findExisting2` 多了「商店链接重叠」一档，位置在商品 ID 之后、标题之前。同时素材包清单开始写 `links`（`pack_api.rs` 的 `meta` 里加的），老包没有这个字段，取到空数组自然跳过。

`downloadLinks` **故意不写进包**：那是本人的订单下载地址，给出去等于把付费内容送人。

**包内自查重**。对方库里本来就有两条同商品/同链接的记录时，导入以前会原样建两条。现在后出现的那条标「包内重复」、默认不勾，要留着自己勾上。只看 `itemId` 和 `links`，**不看标题**——同名不同色的衣装很常见，靠标题判会误杀。

**目录命名不再复用**。原来是 `getDirectoryHandle(name, {create:true})` / `mkdir(dst)`，目录已存在就直接拿来用：两条素材算出同一个目录名时，同名文件被静默覆盖，两条记录还指向同一个 `path`，删一条另一条就悬空。现在统一走 `App.pickFreeFolderName(desired, catLabel, {exists, excludeId})`，撞名依次试 `名字_2`、`名字_3`……最多 99 次，返回 `{name, renamed}`，调用方把改名这件事写进日志 / 进度条。判定占用的两个来源：

1. 已有素材登记的存储路径正好等于「库根\分类\名字」（**同名的不同分类不算冲突**）
2. 磁盘上该目录确实存在（调用方有句柄时传 `opts.exists` 探得更准）

调用点三处：`86-import.js` 的 `copyIntoLibrary`（文件夹导入）、`ensureDownloadFolder`（脚本导入时建下载目录，**只有没本地路径的新素材才挑名**）、`89b-drop-import.js` 的 `importOne`（拖拽导入）。

> 改名的素材之后在编辑页改标题会走 §4 的「同名拒绝」逻辑，会明确报错而不是覆盖 —— 这是有意的，别把那个检查去掉。

### 5.9 开发模式、分包导出、多选交互（2026-11-06）

**开发模式换成自定义协议**（详见 §10 第 0 条）。`热更新.bat` 不再起 Node 静态服务，只设
`VRCLIB_DEV_DIR` 后 `cargo run`；窗口加载 `vrclibdev://localhost/index.html`。
`scripts/dev-server.mjs` 留着但开发时用不上了，只在「想在普通浏览器里看布局」时还有用（那种情况没有 IPC）。

**素材包按 1 GB 分包**。`Packer` 里新增 `PART_LIMIT` 与 `chunkBySize()`：
超过 1 GB 就按 `fileSize` 装箱，同一素材不会被拆开，单个超限的素材自己占一包；
文件名加 `-part1`、`-part2`。**每个包都是完整独立的**（自带 `vrcpack.json` 清单），
不是必须凑齐才能解的分卷 —— 对方收到哪个导哪个。导出对话框会先提示会拆成几个包。

**多选**：
- 开关从右上角工具组挪到结果行左侧（`#btnSelectMode` 现在在 `.toolbar` 里），开启时按钮整体染主色
- 多选模式下支持**拖动连选**：按下那张决定这次是「选」还是「取消」（看它当时的状态），滑过哪张刷哪张。
  实现上直接改 `App.selection` + 就地更新 `.sel-mark`，**不整格重绘**（重绘会把正在拖的节点换掉，拖动当场断）；
  重绘只在 `pointerup` 之后的正常操作里发生。长按进多选的 450ms 定时器加了 `App._paintActive` 判断，避免拖到一半弹出重绘
- 批量条出入有过渡（max-height / 位移 / 透明度），选中数变化时数字弹一下；`prefers-reduced-motion` 下全部关掉

### 5.10 动效与多选浮动区（2026-11-06 晚）

**卡片入场动画换掉了**。原来的 `cardIn` 是「下落 → 过冲 → 回弹再三段收」，一页几十张卡同时弹很吵。
现在是 `opacity 0→1 + translateY(7px)→0`，`.26s`、无缩放无回弹；列表视图 `.18s`。
hover 从 `-3px/.26s 过冲曲线` 收到 `-2px/.18s ease`。改这条曲线改的是 `.grid .card` 的 `animation`，别只改 keyframes 里的数值。

**工作台数据不再懒加载**。`91-workbench.js` 新增 `preload()`，`90-main.js` 在首屏画完的空闲回调里调用
（`afterPaint`，不挡启动）。以前要等第一次打开工作台才读 `workbench.json`，那一下会先显示「没有配置工程」，
多选里点「导入到 Unity」也要多等一次磁盘读。`ensureLoaded()` 保留幂等语义兜底（preload 还没跑完就点了导入）。

**多选浮动区改成 `.fab-dock`**：
- 容器常驻 + `.show` 切状态（原来是 `display:none ↔ flex`，没法过渡）；
  `.fab` / `.fab-exit` 收起时 `opacity:0; visibility:hidden; translateX(34px) scale(.96)`，展开时逐级错开 60ms 滑入
- 三个按钮都补了图标（`parcel` / `box` / `close`），在 `90-main.js` 的 `swapStaticIcons()` 表里登记
- **「退出多选」从批量条里搬出来了**，现在是 dock 最上面那个实心红药丸（`#bulkExit`），悬浮在右下角。
  id 没变，所以 `90-main.js` 的 Esc、`89-pack.js` 导入完成后的 `$('#bulkExit').click()` 都还照常工作
- 右键菜单（`86c-context-menu.js`）在「导出为素材包」下面新增「导入到 Unity」，走 `WB.importToUnity([cur])`

### 5.11 卡片上的筛选入口改成开关（2026-11-06 深夜）

用户反馈：卡片左上角的分类、下方的标签点一下会筛选，但再点一下取消不掉，只能去侧栏一条条关。

- **分类 / 来源 / 角色**统一走 `UI.filterOnly(key, value)`：当前正好只筛了这一个值 → 清空；
  否则 → 切成「只看这一个」。只动这一维筛选，不碰其它条件。
- **标签**在卡片上是两态，走新的 `UI.toggleTagFilter(t)`：未筛 → 加入；已筛 → 取消；已排除 → 也取消。
  `UI.cycleTagFilter`（默认 → 必须包含 → 排除 → 取消）**原样保留**，侧栏标签列表和详情页仍用它 ——
  那两处有足够空间写清三态，卡片上连点两下必须是「开 → 关」。
- 生效中的 chip 会高亮（`.chip.chip-on`，原来只覆盖 `.chip-av`）；分类角标点亮成实心主色
  （`.cat-badge.cat-badge-on`）；开源丝带也改成开关，但没加高亮（45° 旋转的丝带加描边很难看）。
- 提示文案跟着状态变：未筛是「（点击只看此分类）」，已筛是「（已筛选，再点取消）」。

### 5.13 界面改成左侧页签：素材库 / 导入与工程（2026-11-06）

原来的结构是「素材库整页 + 顶栏一个『工作台』按钮打开全屏浮层」。现在左侧固定一列页签
（`.tabrail`，宽 `--tabrail-w` = 78px，窄窗口 54px 只留图标）：

| 页签 | 内容 |
|---|---|
| 素材库（`library`） | 筛选栏 + 工具栏 + 素材网格，跟以前一样 |
| 导入与工程（`workbench`） | 原「改模工作台」，改名并成为页签内容 |

实现要点：

- 切换由 `90-main.js` 里的 `Tab` 模块负责（挂在 `window.AppTab`，提供 `set / current / init`）。
  它只做三件事：切 `body.tab-workbench`、切页签高亮、调 `WB.show()` / `WB.hide()`。

### 5.14 浮动气泡固定右侧、导出动作常驻、页签切换不再闪（2026-11-07）

**③ 导入队列面板常驻，且与下载面板同一套外观 / 交互**：新增 `initIdlePanel()`（`91-workbench.js`），
启动就在右侧摆出面板（收成 34px 竖条、只剩角标），**鼠标移入展开、移出收起** —— 跟下载任务面板一致。

样式逐项对齐 `.dl-panel`：320 宽 / `max-height: 46vh` / 10px 圆角 / 1px `var(--border)` /
`0 8px 26px rgba(0,0,0,.16)` 阴影 / 头部 `6px 8px` + `var(--bg-soft)` / 头部小按钮 11px、`3px 6px`、6px 圆角 /
正文 11px。折叠态同样是 34px 宽、头部竖排、只留角标，原来的竖排文字条（`wb-task-strip`）不再使用。

三个必须注意的点：

- **初始化调用要放在文件末尾**，不能用 `boot()`。`boot()` 在这份文件的中段就可能执行（DOM 已 ready），
  那一刻下面的 `var taskPanel = null` 还没跑，提前建出来的面板随后会被重置成 `null`：
  面板看得见，但关不掉、也折叠不了，下次导入还会再建一个同 id 的。现在挂在 `ensureLoaded()` 前面。
- **位置用 `bottom: 170px`，不要算 `top`**。折叠时高度只有 34px、展开 120px，用 `top` 定位会让面板
  每次展开/收起上下跳 80 多像素 —— 鼠标刚移上去面板就跳走，hover 会来回抖（实测过，会闪）。贴底之后
  两种状态的底边都固定在视口底部 170px 处（右下角是多选时的浮动动作区，约 133px 高 + 22px 边距）。
- **拖动时不能让 hover 收起**：`mouseleave` 里要跳过 `wb-task-dragging`，否则把面板拖出自身范围时
  它会当场塌成竖条，拖动直接断掉。

**④ 右下角浮动动作保持原样**：`#fabDock` 仍然只在多选模式显示
（`renderToolbar` 里 `toggle('show', App.selectMode)`），`.main` 底部留白也还原成 40px。
中途一度把它改成常驻并加了半透明，确认不需要后已撤回。

### 5.15 P2P 传文件（2026-11-07）

目标：和好友直接连起来传素材，支持断点续传。产品决策是**不用中继** —— 打洞失败就直接报错，
所以没有流量成本，代价是部分网络组合用不了（一个手机热点 + 一个校园网基本必失败）。

#### 分工

Rust 只碰磁盘（`src/host/p2p_api.rs`），网络全在渲染层（`js/92-p2p.js`）。
选 WebRTC 而不是 iroh / quinn 的原因很实际：WebView2 自带，**exe 体积和编译时间都不变**。

实测（Edge / WebView2 同为 156.0.4314.58，两个独立进程互联）：

| 配置 | 吞吐 |
|---|---|
| 单通道 16 KB | 23.0 MB/s |
| 单通道 64 KB | 29.4 MB/s |
| 4 通道并行 | 23.1 MB/s（完全不叠加） |
| 裸 TCP 回环（对照） | 1280 MB/s |

上限来自 Chromium 的用户态 SCTP，换块大小、加通道都动不了它。公网上行普遍只有 3.7–12.5 MB/s，
所以这个数字在日常场景不是瓶颈；局域网千兆会从 110 掉到 30。

#### 协议

- 口令 6 位 Crockford Base32（30 bit），**只做房间号，不参与加密** —— 加密由 WebRTC 的 DTLS 负责
- 块 64 KB，**全局连续编号**（跨文件不分段），文件边界用前缀和反查
- 位图落在 `vrclib-data/transfers/<sessionId>.json`，每 256 块刷一次，关窗时 `flush_all()` 兜底
- 会话 ID = 清单（rel + size）的 FNV64。同一份清单必然得到同一个 ID，这是跨进程续传的前提
- 接收端先写 `<dst>/.vrclib-p2p/<sid>/`，`finish` 成功才搬到正式位置；同名文件先留 `.bak`

#### 三个必须记住的坑

1. **sessionId 不能直接当会话键。** prepare 和 open 会用同一个 ID，同进程同时收发时后者覆盖前者，
   `read_block` 于是去打开接收端的临时路径（报「系统找不到指定的路径」）。句柄统一加角色后缀
   `{id}#send` / `{id}#recv`，对外仍暴露 `sessionId` 供配对。**这个 bug 是往返测试抓出来的**，
   光看代码不会发现。
2. **DataChannel 的发送队列 16 MiB 是硬上限。** `send()` 超了直接抛 `send queue is full`，
   背压高水位必须留在 16 MiB 之内（现用 4 MB 高 / 1 MB 低 + `bufferedamountlow` 事件）。
3. **同页两个 PeerConnection 测不出真实吞吐。** 收发抢同一个 JS 线程，并行反而更慢（13 MB/s）。
   要测必须两个独立浏览器进程 + 本地信令，脚本在 `.workbuddy/webrtc-test/`。
4. **信令服务的转发目标写错过一次。** `room.send(role, msg)` 里的参数是「收件人」，不是「发送者」，
   传角色本身消息就在原地打转。这个 bug 是集成测试抓到的，靠读代码很难发现。
5. **写 WebSocket 测试客户端时，握手响应必须逐字节读到空行。** 用 `read(&mut buf[512])` 会把紧跟在
   `101 Switching Protocols` 之后的第一条数据帧一起吞进缓冲区，表现为「对方一条消息都没收到」，
   而实际是测试自己吃掉了。

#### 信令（仅局域网）

只有一种来源：**应用内置**。`src/host/signal_api.rs` 在 Rust 侧起服务，设置 →「点对点传输」→「启动」，
或者点「传给好友」时自动起。端口从 8787 起、被占用自动往后找；本机内网地址用 UDP connect 探测
（比遍历网卡可靠，虚拟网卡一大堆）。服务端是手写的 WebSocket（含一个自带 SHA-1），不引
`tungstenite` 是为了保住 `cargo --offline`。

**地址不用手填**：同一端口段上还开了 UDP 发现应答（`DISCOVERY_TAG = VRCLIB-P2P/1`，
端口 8786–8790）。接收方点「接收文件」时先向 `255.255.255.255` 和本网段广播地址各发一次探测，
开着服务的那台回一句「token + 我的 TCP 端口」，于是：

- 发起方只把 **6 位口令**给对方，不再需要「地址 + 口令」两行
- 接收方输口令就能连，地址是自动找到的，且**不写进设置**（避免把对方的地址留成自己的）
- 探测带随机 token，回执要原样带回才认，防止被别的广播回执带跑
- 自己的回执会被丢弃（同一台机器上服务也开着时，广播会打到自己）

跨网络的服务器（Cloudflare Worker、独立 Node 脚本）已经全部移除 —— 这个功能只服务同一个局域网，
跨网络请用「导出素材包」。如果以后要恢复，协议是「房间号 + 双向转发」，加个 `signalStart` 的变体即可。

顺带修了弹层错配：`.modal-mask` 原来是 490，比导入队列的 `.wb-task`（520）还低，设置页一打开，
右下角那个折叠角标就浮在弹窗上面。现在 modal 560 / toast 570，注释里写的「不能盖弹窗」终于成立。

#### 还没做的

- 断线不会自动重连，要点面板上的「重连」：复用同一口令重新走一遍 SDP，接收端 `open` 读回位图后
  把起始块号告诉发送端，只补缺口
- 没有好友列表 / 设备身份，每次靠口令；也没有传输历史
- 局域网里找不到对方时只报错，不降级 —— 跨网络本来就该走「导出素材包」

## 8. 构建与发布

```bash
# 日常
构建.bat      # fast profile，20 秒左右
# 发布
发布.bat      # release + LTO + strip，90 秒起
# 开发
热更新.bat    # 起 scripts/dev-server.mjs + cargo run，窗口里 Ctrl+R 生效
```

`构建.bat` 和 `发布.bat` 会先 `taskkill /IM VRCLib.exe`，所以程序开着也能直接构建；`热更新.bat` 不结束已有实例，两个窗口同时开会抢单实例锁。手动替换 exe 时如果程序在跑，`copy` 会失败，别以为是构建没产出。

几个必须知道的坑：

- **`CARGO_TARGET_DIR` 必须是纯 ASCII 路径**。中文路径会让 `dlltool` 打不开 `.def`，脚本固定用 `C:\vrclib-build`。
- **`WebView2Loader.dll` 必须跟 exe 同目录**，否则启动瞬间退出（`0xC0000135`）。
- **`tauri` 必须开 `custom-protocol` 特性**（已在 `Cargo.toml` 里常开）。tauri 的 `build.rs` 用 `dev = !custom-protocol` 决定运行模式：不开的话**连 `--release` 都会走 dev 模式**，窗口去加载 `devUrl`（`http://127.0.0.1:8765`），没有开发服务器就是 `ERR_CONNECTION_REFUSED`。2026-11 打包时踩过一次，现场表现是「双击 exe 打开一个 Edge 错误页」。
- **改前端要 `touch src/main.rs`** 再构建，见 §4.4。
- `main.rs` 顶部有 `#![allow(linker_messages)]`：MinGW 下 rustc 的默认清单和 tauri-build 塞的 comctl32 清单同 ID，`ld` 会报 `multiple non-default manifests`。这个 lint 会把链接器 stderr 整体降噪，真要排链接问题可以先注释掉。

## 10. 踩过的坑

0. **开发模式下「数据文件读取失败，已暂停写入」**（2026-11-06 修）：
   现象是启动就弹红色横幅，横幅里的原因是 `host_call not found. Plugin not found`。
   根因不是数据坏了，是**开发模式的页面来源不对**：那时用 `VRCLIB_DEV_URL=http://127.0.0.1:8765`
   把窗口指到 Node 静态服务，Tauri 把这种 http 外部地址判成 `Origin::Remote`，
   而远程来源下**应用自己的命令**（`host_call` / `host_stream` …）默认不放行 —— 于是所有文件读写全废。
   现在改成 `VRCLIB_DEV_DIR=<renderer 目录>`，由 `vrclibdev://localhost` 自定义协议直接读磁盘：
   Windows 上它映射成 `http://vrclibdev.localhost`，走 `is_local_url` 的「用户注册的自定义协议」分支，
   算自家源，IPC 正常，也没有端口可被别的网页冒用。`capabilities/default.json` 里的 `remote.urls` 已删掉。

   改这个东西容易踩的两个小坑：① `Path::canonicalize()` 在 Windows 返回带 `\\?\` 前缀的路径，
   拿它和没处理过的根目录做 `starts_with` 一定失败（表现是页面全白 404）；② `mime_of()` 原来只认图片和压缩包，
   不补 `html/js/css` 就会把页面当二进制下发，窗口黑屏。

1. **`91-workbench.js` 被写空过一次**。Python 脚本里 `io.open(p,'w',encoding=...,newline='\\n')`（双反斜杠）抛 `ValueError`，但 `'w'` 在报错前已经把文件截断。教训：先用 `p + '.tmp'` 写，再 `os.replace`；`newline` 只能是 `'\n'`。这个文件在 git 里是未跟踪状态，动之前先备份到 `C:\vrclib-build\backup\`。
2. **恢复方式**（万一再发生）：程序用 devUrl 跑时，JS 源码在 WebView2 渲染进程堆里。用 ctypes 调 `OpenProcess` / `VirtualQueryEx` / `ReadProcessMemory` 扫 `msedgewebview2.exe`，找 V8 的两字节字符串（UTF-16LE，`'var WB = (function'.encode('utf-16-le')`），解出来就能写回。脚本留在 `C:/vrclib-build/memscan2.py`。
3. **`plan` 的目标目录名带内容签名后缀**（`衣装-abcd1234`），写测试时如果旧目录名刚好等于新 job id 的后缀，新旧目录会重合，断言全错。
4. **面板点击无反应**：先看是不是复用了一个绑了 `mousedown` 的容器。标题栏拖动会 `preventDefault`，点击事件到不了按钮。
5. **`waitTerminal` 这类回调**：JS 没有类型检查，`done(字符串)` 和 `done(数组)` 都能写出来，错在运行时才炸，而且炸在 Promise 里不会中断队列循环——只表现为「没反应」。改回调签名时把两边一起改。
